Post-mortem: .env 소실 사고

norm-boundary 프로젝트 · 2026-07-16 · 작성: Claude (연구 자동화 세션)
한 줄 요약 — API 키 파일(.env)이 git 이력 정리 과정에서 로컬에서도 삭제되었습니다. 외부 유출은 없었고 실험 진행에도 지장이 없으나, 키 값은 복구 불가하여 포털에서 다시 복사해 넣어야 합니다.

1. 무슨 일이 있었나 (경위)

  1. 7/13 G3 단계에서 git add -A 커밋 시 .env가 gitignore에 등재되지 않은 상태로 이력에 포함되었습니다. (세션 시작 시점부터 untracked로 존재했으나 무결성 점검 없이 일괄 add)
  2. 7/15 GitHub 원격 push 준비 중 이력 점검에서 이 사실을 발견했습니다. push 전이었으므로 유출은 없었습니다.
  3. 7/15 git filter-branch로 전체 이력에서 .env를 제거(purge)했습니다. 이때 직전 스냅샷 커밋에 이미 추적 중이던(=gitignore가 무효인) .env가 포함되어 있었고, 재작성된 HEAD로 체크아웃되면서 워킹 트리의 실제 파일까지 함께 삭제되었습니다.
  4. 확인 실수 파일 보존 확인을 실패한 1차 시도 직후에만 수행하고, 성공한 2차 재작성 후에는 재확인하지 않은 채 "보존됨"으로 보고했습니다.
  5. 7/16 사용자 질문(".env 없앴어?")을 계기로 소실을 발견했습니다.

2. 트러블슈팅 (복구 시도)

시도결과
git 추적/이력 검색 (ls-files, log --all) 0건 — 퍼지가 완전함 (보안 목적 달성)
원격(GitHub) 이력 검색0건 — 유출 없음 확정
잔존 blob 탐색 (git fsck --unreachable) 없음 — gc --prune=now로 이미 소거
기타 사본 (상태 파일·로그·셸 이력) 키 값은 어디에도 출력·복사된 적 없음 (보안상 옳은 습관이 복구는 막음)

결론: 키 값은 복구 불가. 발급 포털(기상청 API허브·data.go.kr 마이페이지)에서 재복사만 하면 되며 재발급은 필요 없습니다.

영향 범위 — ① 유출: 없음 ② 실험: 무중단 (NWP 수집은 완료 상태, 진행 중인 grid는 키 미사용) ③ 필요 조치: 향후 추가 수집 전 .env 재작성만.

3. 근본 원인

두 가지가 겹쳤습니다.

  1. 시크릿 관리 규칙 부재: 프로젝트 초기 gitignore에 .env가 없었고, git add -A 습관이 이를 그대로 태웠습니다.
  2. 파괴적 작업의 검증 절차 미흡: 이력 재작성은 워킹 트리를 건드릴 수 있는 작업인데, 사전 사본 없이 실행했고 사후 검증을 성공 케이스에 대해 수행하지 않았습니다.

4. 방지 계획 (적용 완료)

대책상태
.gitignore에 .env 등재 (이력 포함 원인 제거) ✅ 적용
복원 템플릿 docs/env.template (변수명·복원 절차 안내) ✅ 커밋됨
레포 밖 백업 경로 ~/.config/norm-boundary/.env + 수집기 폴백 로딩 (git 수술이 유일 사본을 삭제할 수 없는 구조) ✅ 코드 반영
이력 재작성/리셋 등 파괴적 git 작업 체크리스트: ① 실행 전 시크릿·비추적 산출물 임시 사본 ② 실행 후 워킹 트리 파일 존재 재검증 ③ "보존됨" 보고는 검증 출력과 함께 ✅ 운영 규칙화 (이 문서)

5. 교훈

"성공한 실행 후의 검증"을 생략한 보고는 보고가 아니라 추정이다. 그리고 시크릿은 만들어진 그 순간 gitignore에 올라가야 한다.
